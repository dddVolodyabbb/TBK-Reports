# Android Release-подпись

Здесь лежит постоянная подпись Android-приложения «ТБК Отчёт». Без неё нельзя выпустить
обновление, которое установится поверх уже установленной версии: телефон откажет, если
подпись другая.

## Что за файлы

| Файл | В Git | Что это |
|---|---|---|
| `tbk-report-release.keystore` | нет | **Рабочий ключ.** Псевдоним ключа `tbk-report`. Им подписаны все релизы, начиная с Android version code 5. |
| `tbk-report-release.password` | нет | **Пароль к рабочему ключу** (одна строка). Один и тот же пароль для хранилища и для ключа. |
| `android-signing.props` | да | Подключает рабочий ключ к Release-сборке `TbkReport.Android.csproj`. Пароль берётся из переменной окружения `TBK_ANDROID_SIGNING_PASSWORD`, в файле его нет. |
| `README.md` | да | Этот файл. |
| `android-release.keystore`, `android-release.password` | нет | **Не используются.** Остатки первой неудачной попытки создать ключ 27.09.2026 (за 14 минут до рабочего). Пароль пустой, ключ не совпадает с рабочим, ни один скрипт и проект на них не ссылается. Ими ничего не подписано: удалить можно без последствий. |

`*.keystore` и `*.password` исключены из Git в `.gitignore`. Рабочие ключ и пароль хранить
и бэкапить только вместе: ключ без пароля бесполезен. Если они пропадут, следующее
обновление на телефонах придётся ставить только после удаления старой версии (сначала
экспорт данных).

## Как собирать

Release-APK собирает только `scripts/Build-AndroidRelease.ps1`. Скрипт:

1. проверяет, что рабочие ключ и пароль на месте, и останавливается, если их нет. Так APK
   случайно не подпишется тестовым сертификатом Android Debug;
2. читает пароль из `tbk-report-release.password` в `TBK_ANDROID_SIGNING_PASSWORD`;
3. собирает и подписывает `*-Signed.apk` в `src/TbkReport.Android/bin/Release`.

Обычный `dotnet build -c Release` без скрипта падает на подписи APK («java.exe завершилась
с кодом 2»), потому что пароль не задан. Это не ошибка кода. Для проверки компиляции без
подписи достаточно Debug-сборки.
